# Changelog

What Super3DX+ adds or changes compared with [Re3DX+](NOTICE.md). Longer explanations are in `docs/`.

## Unreleased

- **The opposite carriageway has its traffic again** (issue 45): the arcade's own second traffic system (`yt::COnComerManager`, six slots on the far side of the divider) is wired into the port, so divided roads have cars coming the other way again, as on the arcade (and as Re3DX+ had lost too). Courses without a divided road (Nagoya, Osaka, Hakone) stay as they were, and the player's physics are bit for bit unchanged. The update is a usual one: the setup rebuilds the game program in a few minutes; the converted data and the saves are not touched.

## 1.0.0

The first numbered release. Everything below the next heading is the feature list; this is what is new since the last update.

**Updating needs the data converted again** (about an hour: the setup does it by itself and copies your saves across). The menu data changed: the commas in story dialogue, the tuning card's colour row, and the title glyph numbers. Android and the Raspberry Pi need `setup-android` / `setup-pi` run again afterwards. **Online versus: everyone in a room must be on this version** (the protocol is 172).

- **macOS** (thanks to GT-610's pull request #43): the same game on Apple silicon (an Intel Mac should work too, untested) over OpenGL 2.1 (`build.py --target macos`, `setup.sh`). The packaged `Super3DX+.app` holds the player and the data, so it can go in Applications; its saves are in `~/Library/Application Support/Super3DX+/save`. The loading thread is on by default there (BACKGROUND LOADING in the debug options turns it off).
- **Time attack records you can share** (`docs/RECORDS.md`): the ranking lives in a `records` folder in the save folder. Your runs are in `records/my-times.rec`; any other file put in the folder is merged into the ranking and the course record, with the game running. Your personal bests are in `records/card<n>.dat`. The files are packed and checked, so a time cannot be typed in by hand. Your old `ranking` and `records<n>` files are read once.
- **Story and 10-in-a-row:** the end sequence (the TIME row, the win streak animation, the mileage after the tuning work, the tuning install animation); the gear is kept through a story select's second race and a cutscene's restart (issue 41); a 10-in-a-row restart is no longer money-shifted; the commas in story dialogue, the tuning card's colour row and the title glyphs are right (the "C S" title, issue 38, with the data converted again).
- **First-person (bumper) view** is the arcade's own camera in smooth motion too, as at 60 Hz; the 10-in-a-row restarts no longer throw it off the road.
- **New options:** ANTI-ALIASING OFF (with 2X and 4X), RESOLUTION SCALE (50% to 100%), the touch controls' BUTTON OPACITY, and on the Mac BACKGROUND LOADING. The quality governor has two more resolution steps for weak GPUs (issue 32).
- **Versus:** a player's READY and AUTO READY work with the mouse and touch (issue 26); the race time is longer for longer races; the pilot drives while you are in the pause menu; joining, leaving and crashing have sounds; another player's two-line title is two lines in the player box.
- **Android:** the APK build retries `zipalign` and falls back (issue 44); a phone is asked for a high refresh rate in a way it accepts (issue 36).
- **Street lights:** the conversion now makes the street and building lights of Osaka, Nagoya and Fukuoka (`lights_<city>.bin`). A build from the setup had none there: only Tokyo's were made.
- **Smaller:** `--save` makes its folder when it is missing; `build.py package` keeps the saves it finds; the INFORMATION screen shows the version.

## What it has (the whole list)

## Input and menus

- Controller-first menus: full pad and keyboard control on every screen, with rebindable keys, pad buttons and analog axes
- Controller input filtering, deadzone, response and button-steering speed tuning
- Controller vibration (wall hits, expansion joints, tyre slip) with adjustable strength
- TOUCH LAYOUT (the touch controls' screen, formerly KEY LAYOUT, issue 18): besides the three groups of touch keys, the race's gauges can be dragged and resized: the dials, the speed plate, the gear shifter, the rank and distance, the time left, the map and the rival info (50% to 200%, about their own middle; a console left alone stays exactly where it was). The arcade-style HUD is untouched.
- ANTI-ALIASING can now be turned OFF (the lightest setting for a slow GPU, with 2X and 4X as before), and the new RESOLUTION SCALE (50% to 100%) sets how sharp the 3D is drawn, under the frame rate governor's own steps (issue 32). Graphics screen on Android; AA takes effect at the next start
- CAMERA SHAKE (in the game settings): smooths out the view's shake at speed and over rough road, 0% to 100%
- TOUCH LAYOUT: the shift up and shift down keys are now groups of their own, sized and placed apart from the pedals and from each other (a layout saved before keeps them where they were)
- Android: coloured static on some road stretches (Nagoya's first reflection cube has one face of another size, which Vulkan read past its edge; issue 24)
- NETWORK OPTIONS shows how the last host or join attempt went (no answer, version mismatch, host closed...) instead of "not connected"; the same line goes to the log
- Windows: the game asks laptops with two graphics cards to use the fast one (NVIDIA Optimus and AMD switchable graphics; Windows' Graphics settings can still override it)
- Steering wheel support (untested on hardware): wheel axes and buttons are bindable, and force feedback (steering pull, centering, damping, road effects) through SDL haptic, with a WHEEL list in KEY BINDINGS for the device and gains
- Rebuilt main menu flow: PLAY / SETTINGS / EXIT, then car selection, then Solo / Versus / Car settings
- Stock, Full Tune and Hell's Tuning starting points (Hell's Tuning begins the story on Ch. 101)
- Restored AT / MT transmission select screen
- Special color selection for cars
- Restored suspension lowering for tuned cars
- Volume mixer
- GAME OPTIONS has a GRAPHICS sub-menu now: textures, reflection, HD textures, wet road, anti-aliasing, resolution, window mode and DISPLAY OPTIONS moved into it
- Versus: the second race of a session could stand still at its start on both machines for ever (the clock comparison kept the last race's numbers, so the client thought it was thousands of frames ahead of the host and dropped every step, and a machine that takes no step sends nothing); it starts over with each race now
- SMOOTH MOTION (GAME OPTIONS > GRAPHICS, on by default): on a display that is not 60 Hz (90, 120, 144 Hz) and in versus races the physics steps run on the clock's time and the car, camera, tyres, rivals and traffic are drawn blended between the last two steps, so motion is even at any refresh rate; a versus client follows the host's clock by running a little fast or slow (up to 3 %) in place of dropping or doubling a step. Costs one frame (16 ms) of delay; menus, HUD and effects are unchanged. `MT3DX_INTERP=0|1` forces it for a test
- Android: a 60 FPS LOCK (GAME OPTIONS > GRAPHICS) for phones with a 90 or 120 Hz panel (issue 32): it asks the system for 60 Hz and, on a panel that stays at a whole multiple of 60 (120 Hz), draws one frame every second refresh, each on its own game step, instead of two frames per step
- DISPLAY OPTIONS on PC (GRAPHICS), with a BLACK LEVEL setting and a bar of greys to judge it by: pulls the blacks down for displays or drivers that show the picture grey and washed out (a limited range signal on a full range monitor, Auto HDR, colour enhancement); 50% undoes a 16-235 limited range
- Option to skip the intro cutscenes, and restored missing intro cutscenes
- Information screen

## Platforms and builds

- Export (English) build support and an English language layer
- Raspberry Pi 5 support with composite CRT output (and optional HDMI)
- Windows, Linux and updated Android players
- macOS support: the same GLES2 sources run on a desktop OpenGL 2.1 context (`platform/macos/gl_mac.c` maps the EXT/APPLE entry points for framebuffers, mipmaps, blits, multisampling and vertex arrays, and translates the shaders' precision qualifiers to GLSL 1.20); `build.py --target macos` (the default on macOS), and `play.command` and a `Super3DX+.app` in the package
- macOS: the loading thread is on by default (the races hitched without it on an M2; a BACKGROUND LOADING row in the debug options turns it off (the WINDOW MODE row is there on Apple silicon too, which the arm test had left out as the Pi's), for a quicker first load and more hitches in the races: the next start), the game window's close button quits the game (SDL sent no quit while the loading thread's hidden window was open; this also fixes the same on Windows with `--loader-thread`), the generated GL stubs are 4-byte aligned for the arm64 linker, and a GL function the driver lacks is named in the log
- macOS setup and data tools: the converters accept the Arial fonts macOS ships, and ffmpeg 9's own Vorbis encoder where it no longer includes libvorbis
- Windowed / fullscreen mode (F11 or Alt+Enter), remembered between starts
- `build.py` and `tools/pipeline.py` build driver: Python 3.9+ and a C compiler, no WSL
- Guided setup (`setup.bat` / `setup.sh`): installs what it needs, finds and checks your game folder, builds, and explains failures in plain language
- Updates only redo what changed: a new version usually rebuilds just the game program in minutes, keeping your data and saves
- `setup-pi`: builds and installs the game on a Raspberry Pi over the network, with the boot service and composite/HDMI output
- `setup-android`: builds one self-contained Android app (any OS) and can install it over USB
